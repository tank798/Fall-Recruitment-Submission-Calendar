# 数据层问题清单

本文记录「秋招时间表」数据读取、写入、导出和筛选方面的已知风险及修复结果。当前清单中的 F1–F2、P1–P10 均已处理，后续若发现新的数据问题请继续补充复现样例和回归用例。

审查环境：Node 22+ · Next 16.3.3 · React 19.2.8 · xlsx 0.18.5 · zod 4.5.4 · pnpm 10.15.0。

## 已修复

### ✅ F1 · 并发写入静默丢记录

`createSchedule`、`updateSchedule`、`deleteSchedule` 现在用同一把串行锁包住完整的读—改—写事务，并采用原子写入、文件与目录 `fsync`、写前备份、损坏文件隔离和写后回读校验。单条损坏记录会单独进入 `data/quarantine/`，不会连坐整份数据。

### ✅ F2 · Next 运行时读取 Excel 导致整站 500

Excel 读取异常现在会被捕获，应用降级为空数据启动并提示使用 `pnpm import:excel`。独立导入脚本仍在纯 Node 环境中执行，避免把 `xlsx` 的文件系统依赖带入 Next 页面运行时。

### ✅ P1 · 导出的 Excel 无法重新导入

导出格式统一为 `总览` + `JD` 两张表。总览使用规范列：公司、岗位、日期、时间、环节、具体事项、地点、备注、来源链接及记录元数据；JD 表包含 JD、招聘批次、来源链接和待补日期进展。解析器识别规范表后逐字段回读，因此环节、时间、地点、链接、备注和 JD 可以闭环恢复。

### ✅ P2 · 跨年进度年份推断错误

没有显式年份的进度行若推断日期早于投递日期，会自动按下一自然年处理。例如 2026-09 投递后的 `1/15 终面` 会解析为 2027-01-15，不再从届别视图中消失。

### ✅ P3 · 无投递日期的未标注进展被丢弃

没有投递日期时，无法生成日程的原始进展会写入对应岗位的 `pendingProgress`（待补日期进展），并在岗位详情中展示；有投递日期时仍会附加到投递记录备注。导出和回导也会保留这部分内容。

### ✅ P4 · 阶段自动识别漏判

阶段识别补充了 `专业面`、`综合面`、`部门面`、`交叉面`、`复试`、`初试`、`无领导`、`机考`、`上机` 等常见写法，并归一到五个一级环节：投递、测评、笔试、面试、Offer。

### ✅ P5 · 导出忽略届别与筛选条件

时间表的导出链接会携带当前届别、环节筛选和搜索关键词。`/api/export` 按相同条件过滤日程，并只导出这些日程关联的岗位与 JD；不带参数时仍可导出完整数据。

### ✅ P6 · JD 表按压缩行号对齐

解析器保留物理空行，并优先按公司+岗位键匹配。遇到 `=总览!A2` 一类公式时，只解析公式明确指向的单元格，不再使用两张表各自压缩后的行号作为静默兜底。

### ✅ P7 · 届别选择不持久化

当前届别写入浏览器 localStorage，刷新后恢复上次选择；浏览器禁用存储时自动回退到默认届别，不影响当前会话。

### ✅ P8 · 网页新增记录不会生成岗位

网页新增或编辑日程会在同一事务中按公司+岗位 upsert `Job`。公司与岗位页、详情 JD 和表单联想会立即使用最新岗位索引；已有 JD、分类、批次和来源链接会被保留。

### ✅ P9 · 依赖全部使用 `latest`

运行依赖和开发依赖均已固定为具体版本，`pnpm-lock.yaml` 与 `package.json` 保持一致，安装结果可复现。

### ✅ P10 · 缺少 lint 与测试

新增 ESLint flat config 和 `pnpm lint`。新增 `scripts/verify-excel-parser.ts`，覆盖导出回导、跨年日期、未定日期进展、阶段识别和 JD 公式对齐；`scripts/verify-datastore.ts` 覆盖并发写入、损坏恢复、脏记录隔离、空数据启动和网页岗位索引。`pnpm test` 会依次运行两套回归。
